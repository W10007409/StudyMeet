# 선생님 수업 화면 요건정의 및 설계

- 작성일: 2026-08-07
- 대상: StudyMeet 화상 1:1 튜터링의 선생님측 웹 화면
- 상위 설계: `2026-08-06-studymeet-video-tutoring-design.md` (이하 "본 설계")
- 상태: 설계 확정, 구현 계획 대기

---

## 1. 배경과 범위

본 설계는 아이측 태블릿 앱을 정의했으나, 선생님 클라이언트의 형태는 §12 오픈이슈 #3으로 미정 상태였다. 이 문서가 그것을 확정한다.

### 1.1 범위 분리 — 편성 시스템은 이 문서가 아니다

인터뷰 중 **수업 일정·배정 시스템이 존재하지 않는다**는 사실이 확인되었다. 이는 요청된 "선생님 화면" 안에 서로 독립적인 두 개가 들어 있음을 뜻한다.

| | A. 수업 편성 시스템 | B. 선생님 수업 화면 (이 문서) |
|---|---|---|
| 하는 일 | 학생·선생님 등록, 일정 생성, 배정·매칭, 취소·노쇼·대체 처리 | 실시간 화상, 학습화면 공유, 이탈 표시, 수업 진행 |
| 주 사용자 | 운영자 | 선생님 |
| 성격 | CRUD·스케줄링·운영 정책 | 실시간·WebRTC·상태머신 |
| 규모 | 선생님 3,000명 × 10분 슬롯. 매칭 규칙·취소 정책·정산 연동이 딸림 | 본 설계 §4·§5·§9의 연장 |
| 화상 방식과의 관계 | 무관 | 직결 |

**A와 B가 만나는 지점은 §7의 인터페이스 6개뿐이다.** 그것만 고정하면 A 없이 B를 완성할 수 있으므로, B를 먼저 만들고 A는 별도 스펙으로 분리한다. A를 먼저 하면 운영 정책 결정이 선행되어야 해 화상 쪽 진도가 멈춘다.

본 설계에서 학습 화면을 "슬롯"으로 추상화하고 화상 엔진을 `VideoEngine` 인터페이스 뒤에 둔 것과 같은 방식이다.

### 1.2 확정된 전제

| 항목 | 값 | 근거 |
|---|---|---|
| 선생님 기기 | **PC 브라우저** (데스크톱·노트북), 최소 1280px | 인터뷰 |
| 수업 흐름 | **선생님이 재량껏 결정.** 고정 시간표 없음 | 인터뷰 |
| 학습화면 제어 | **양방향** — 누구든 넘기면 같이 움직임 | 인터뷰 |
| 이탈 시 선생님 수단 | **목소리만.** 아이 쪽 PIP에 [수업으로 돌아가기] 버튼 | 인터뷰 |
| 수업 기록 | **간단한 메모**, 종료 시 저장 | 인터뷰 |
| 준비 실패 연락 | **푸시 우선**, 연락처는 마스킹 후 열람 | 인터뷰 |
| 동시 진행 | 1:1 고정. 여러 학생 동시 없음 | 본 설계 §1.1 |

## 2. 설계 원칙 — 시스템이 밀지 않고 선생님이 당긴다

인터뷰에서 "선생님이 재량껏 할 수 있도록"이 요구되었다. 이를 화면 전체의 단일 원칙으로 삼는다.

- 수업 간 **자동 전환 없음**. 목록에서 선생님이 직접 고른다.
- 아이가 입장해도 **자동 시작 없음**. 선생님이 [수업 시작]을 누른다.
- **자동 종료 없음**. [수업 종료]가 유일한 정상 경로다(본 설계 §4.5).
- 시간 보상도 시스템이 계산하지 않는다. 누적 끊김 시간만 보여주고 판단은 선생님이 한다(본 설계 §4.6).

시스템이 강제하는 것은 **안전장치 둘뿐**이다: 하드 타임아웃 30분, 선생님 연결 소실 90초 후 자동 종료. 둘 다 방치된 방을 정리하기 위한 것이지 진행을 재촉하는 장치가 아니다.

## 3. 화면 구성

```
┌─────────────────────────────────────────────────────────────────┐
│ 김민준 (초3) · 경과 04:12 · 🟡 다른 화면 00:15 · 끊김 0:24  [수업 종료] │
├───────────────────────────────┬─────────────────────────────────┤
│                               │                                 │
│      학습화면 (책 지면)         │       아이 영상 (크게)            │
│                               │                                 │
│   ◀ 12 / 48 ▶   ✋포인터        ├─────────────────────────────────┤
│                               │  내 영상 (작게, 접기 가능)         │
│                               ├─────────────────────────────────┤
│                               │  메모                            │
│                               │  ┌───────────────────────────┐  │
│                               │  │                           │  │
│                               │  └───────────────────────────┘  │
└───────────────────────────────┴─────────────────────────────────┘
        약 58%                              약 42%
```

### 3.1 배치 근거

- **아이 영상을 크게 둔다.** 표정과 집중도를 읽는 것이 선생님의 핵심 작업이고, 이탈도 여기서 먼저 눈에 띈다. 아이 화면에서는 로컬 프리뷰를 숨겼지만(본 설계 §8.1 — 아이는 자기 얼굴을 보면 산만해진다) 선생님은 반대로 상대를 크게 봐야 한다.
- **내 영상은 작게, 접을 수 있게.** 선생님은 자기 상태를 확인할 필요가 있지만 상시 크게 볼 이유는 없다.
- **상단바에 학생·경과·이탈·끊김·종료를 모은다.** 수업 중 시선이 한 줄에만 머물게 한다.
- 아이 화면과 달리 **경과 시간을 표시한다.** 본 설계 §4.6에 따라 타이머는 선생님에게만 보인다.

## 4. 상태 흐름

```
[오늘 수업 목록]        선생님이 직접 고른다. 자동 전환 없음
      │ [입장]
      ▼
   [대기실]             시작 5분 전부터. 학생 준비상태 표시
      │ 아이 입장 감지 → [수업 시작]   (이것도 선생님이 누른다)
      ▼
   [수업 중]
      │ [수업 종료]      유일한 정상 종료 경로
      ▼
  [메모 확정] → 목록으로
```

### 4.1 오늘 수업 목록

`GET /teacher/{id}/sessions` 결과를 시간순으로 보여준다. 각 행에 학생명, 시각, 교재, 준비상태 배지. 시작 5분 전이 된 수업만 [입장]이 활성화된다.

편성 시스템(A)이 없는 동안에는 스텁이 고정 목록을 반환한다.

### 4.2 대기실

본 설계 §4.4에 따라 수업 시작 5분 전부터 열린다. 화면은 다음을 보여준다.

- 학생 정보와 교재
- **학생 준비상태** — 아이 앱의 무음 프리체크 결과(본 설계 §7.5)
- 아이 입장 여부
- [수업 시작] 버튼

준비 실패 시 §6의 대응 UI가 이 자리에 나타난다.

### 4.3 종료

[수업 종료]를 누르면 메모를 확정하고 세션을 닫은 뒤 목록으로 돌아간다.

**확인 다이얼로그는 두지 않는다.** 연속 수업에서 한 번 더 누르게 하는 것은 마찰이다. 대신 이것이 다음을 **요건으로 만든다**:

> **종료된 수업은 예정 시각 + 30분 이내라면 선생님이 다시 입장할 수 있어야 한다.** 재입장 시 기존 메모를 이어서 쓴다. 아이 앱도 같은 방에 재접속할 수 있어야 한다.

확인 절차를 없앤 대신 되돌릴 길을 여는 것이다. 둘 중 하나는 있어야 하고, 연속 수업에서는 후자가 낫다. 30분은 본 설계 §4.5의 하드 타임아웃과 같은 값을 쓴다.

재입장을 지원하지 않기로 한다면 **확인 다이얼로그를 반드시 되살려야 한다.** 이 둘은 함께 결정된다.

## 5. 이탈 표시

본 설계 §4.2의 상태 모델을 그대로 화면에 옮긴다.

| 상태 | 상단바 | 아이 영상 영역 |
|---|---|---|
| `IN_CLASS` | 표시 없음 | 정상 |
| `PIP` | 🟡 다른 화면 00:15 | 영상 위 얇은 노란 테두리 |
| `SCREEN_OFF` | 🟠 자리비움 00:08 | "화면이 꺼져 있어요" + 오디오 파형 |
| `DISCONNECTED` | 🔴 연결 끊김 00:22 | "다시 연결 중…" |

### 5.1 조작 버튼을 두지 않는 것은 의도다

인터뷰에서 선생님의 복귀 유도 수단은 **목소리**로 확정되었다. PIP 상태에서도 오디오는 살아 있으므로 "○○아, 돌아와" 한마디면 닿는다.

여기에 [알림 보내기] 같은 버튼을 두면 선생님이 말 대신 그것을 누르게 된다. 아이에게는 사람이 부르는 편이 낫고, 화면도 단순해진다. **이탈 관련 조작 버튼은 두지 않는다.**

### 5.2 누적 끊김 시간

상단바에 항상 표시한다. 시간 보상이 선생님 재량(본 설계 §4.7)이므로 판단 근거를 눈에 붙여 둔다.

⚠️ 본 설계 §4.3에 기록된 대로, P2P 전환 이후 이 값은 **클라이언트 보고 기반**이라 정확도가 낮다. 앱이 완전히 죽은 구간은 시그널링 소켓 단절 시각으로 역산한다. 이 한계를 선생님 교육 자료에 명시한다.

### 5.3 아이 쪽 복귀 경로 — 본 설계 변경 사항

선생님에게 조작 수단이 없으므로, **아이가 스스로 돌아올 길이 반드시 있어야 한다.** 본 설계 §5.1의 PIP `RemoteAction` [수업으로 돌아가기] 버튼은 Phase 0 범위 밖으로 미뤄져 있었으나, 이 결정으로 **제품 필수 기능으로 승격**한다. Phase 2에 편입한다.

## 6. 준비 실패 대응

대기실에서 학생 준비 실패가 확인되면 다음을 표시한다.

```
⚠ 민준이가 카메라 권한을 허용하지 않았어요
   [알림 보내기]   연락처 010-****-1234 [보기]
```

### 6.1 푸시 우선

[알림 보내기]는 아이 기기로 푸시를 보낸다. 실패 유형 두 가지를 모두 덮는다.

| 상황 | 동작 |
|---|---|
| 아이가 앱에 있는데 권한 거부 | 푸시가 도착하고, 앱이 열려 있으면 인앱 안내로 렌더된다 |
| 아이가 앱을 켜지 않음 (노쇼) | 푸시가 유일한 도달 수단이다 |

본 설계 §7.3에서 한 번 삭제했던 보호자 푸시 경로가 여기서 돌아오지만, **자동 발송이 아니라 선생님이 판단해 누르는 것**이라는 점이 다르다. 자동 발송은 오작동 시 학부모에게 잘못된 알림이 나가지만, 선생님 발송은 상황을 본 사람이 보낸다.

### 6.2 연락처는 마스킹

- 기본 표시는 `010-****-1234`.
- [보기]를 눌러야 전체가 보이고, **누가 언제 열람했는지 기록**한다(`POST /contacts/{studentId}/reveal`).
- 아동 개인정보이므로 상시 노출하지 않는다. 감사 대응이 가능해야 한다.

### 6.3 권한이 없어도 수업은 시작된다

본 설계 §7.4에 따라 [수업 시작]은 준비 실패 상태에서도 활성화된다. 카메라 권한이 없으면 오디오와 학습화면만으로 진행하고, 선생님 영상은 아이에게 단방향으로 보인다. **수업 자체를 막지 않는다.**

## 7. 학습화면 공유

본 설계 §9의 DataChannel 위에 얹는다.

### 7.1 양방향 동기화

누구든 페이지를 넘기면 상대도 함께 움직인다. 충돌은 **마지막 조작 우선(LWW)** 으로 해소한다. 각 `page_sync` 메시지에 단조 증가 카운터를 실어 보내고, 수신측은 자기가 마지막으로 적용한 값보다 큰 것만 적용한다.

10분 1:1에서 사람 손 속도로 오가는 조작이므로 이 이상의 합의 알고리즘은 과하다.

### 7.2 누가 넘겼는지 보여준다

동기화가 조용히 일어나면 "내가 넘긴 게 아닌데 왜 움직이지"가 된다. 페이지가 바뀔 때 1.5초 토스트를 띄운다: **"선생님이 넘겼어요"** / **"민준이가 넘겼어요"**.

### 7.3 포인터

선생님이 학습화면을 누르고 있는 동안 아이 화면 같은 위치에 원이 표시된다. 떼면 사라진다. `pointer` 메시지(본 설계 §9.1)를 그대로 쓴다.

### 7.4 아이가 촬영 중일 때

본 설계 §6.2에 따라 아이가 [📷 사진 찍기]를 누르면 학습화면 자리가 **아이의 후면 카메라 뷰파인더로 전환**되고 "○○이가 사진 찍는 중" 배지가 붙는다. 선생님이 실시간으로 "조금만 위로!" 코칭할 수 있어야 하므로, 이 전환은 선생님 화면에서 가장 큰 영역에 일어난다.

## 8. 메모

우측 하단 한 칸의 자유 입력.

- 타이핑 후 3초 debounce로 자동 저장한다.
- [수업 종료] 시 확정되어 `POST /sessions/{id}/end` 에 함께 실린다.
- **별도 저장 버튼을 두지 않는다.** 연속 수업에서 저장을 잊는 것이 더 큰 손실이다.

구조화된 평가 항목은 두지 않는다. 10분 수업 사이에 항목을 채우는 것은 부담이고, 필요해지면 별도 리포트 기능으로 분리한다.

## 9. 외부 인터페이스

편성 시스템(A)이 없는 동안 이 6개 뒤에 스텁을 둔다. 진짜 A가 붙어도 화면은 바뀌지 않는다.

| 엔드포인트 | 용도 |
|---|---|
| `GET /teacher/{id}/sessions?date=` | 오늘 수업 목록 |
| `GET /sessions/{id}/readiness` | 학생 준비상태(프리체크 결과) |
| `POST /sessions/{id}/nudge` | 복귀·준비 알림 푸시 발송 |
| `POST /sessions/{id}/end` | 종료. 본문에 `{ note, disconnectedSec }` |
| `GET /sessions/{id}/token` | 시그널링·미디어 접속 토큰 |
| `POST /contacts/{studentId}/reveal` | 연락처 열람. 열람 기록을 남긴다 |

수업 목록 항목의 최소 형태:

```
{ sessionId, studentName, studentId, scheduledAt, durationMin, bookTitle, status }
```

## 10. 기술

Phase 0에서 만든 `signaling/public/teacher.html` 의 WebRTC 코드를 승계한다. 시그널링 접속, ICE 후보 버퍼링, `selectedCandidatePair` 판정이 이미 실동작으로 검증되었다(브라우저 두 개가 서버를 거쳐 협상하고 `connected` 도달).

`selectedCandidatePair` 판정 로직은 Android 앱과 동일한 규칙을 쓴다. 양쪽 로그를 `signaling/coturn.md` 의 같은 집계 규칙으로 처리해야 하기 때문이다.

프론트엔드 프레임워크는 §11 오픈이슈로 남긴다.

## 13. 상위 설계에 반영할 변경

이 문서의 결정이 `2026-08-06-studymeet-video-tutoring-design.md` 를 두 곳 바꾼다.

1. **§12 오픈이슈 #3 해소** — 선생님 클라이언트는 **PC 브라우저 웹**으로 확정.
2. **§5.1 `RemoteAction` 승격** — PIP 창의 [수업으로 돌아가기]는 Phase 0 범위 밖이 아니라 **제품 필수 기능**이다. 선생님에게 조작 수단을 두지 않기로 한 이상, 아이가 스스로 돌아올 유일한 경로이기 때문이다. Phase 2에 편입한다.

## 14. 결정 요약

| 항목 | 결정 |
|---|---|
| 선생님 기기 | PC 브라우저, 최소 1280px |
| 레이아웃 | 좌 58% 학습화면 / 우 42% 아이 영상·내 영상·메모 |
| 아이 영상 | **크게** (아이 화면과 반대 — 표정을 읽어야 함) |
| 내 영상 | 작게, 접기 가능 |
| 진행 방식 | **선생님이 당김.** 자동 전환·자동 시작·자동 종료 없음 |
| 종료 확인 | 다이얼로그 없음. 대신 **예정 시각 +30분 내 재입장 가능**이 요건이 됨 (§4.3) |
| 안전장치 | 하드 타임아웃 30분, 선생님 연결 소실 90초 |
| 이탈 표시 | 배지 + 타이머 + 영상 영역 변화. **조작 버튼 없음** |
| 이탈 대응 수단 | 선생님은 목소리. 아이는 PIP의 [수업으로 돌아가기] |
| 누적 끊김 시간 | 상단바 상시 표시 (정확도 한계 명시) |
| 학습화면 제어 | 양방향, LWW, 넘긴 주체 토스트 표시 |
| 메모 | 자유 입력 1칸, 3초 자동 저장, 종료 시 확정 |
| 준비 실패 | 푸시 우선, 연락처 마스킹 + 열람 기록 |
| 권한 없는 수업 | 진행함 (오디오 폴백) |
| 편성 시스템 | **별도 스펙.** 인터페이스 6개 뒤에 스텁 |
