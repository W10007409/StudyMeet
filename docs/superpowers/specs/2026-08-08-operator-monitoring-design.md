## 1. 범위 — 모니터링 도구이지 관리 도구가 아니다

편성 설계 §6.2는 운영자 화면으로 일곱 가지를 나열했다. 인터뷰에서 **등록·배정은 다른 시스템이나 개발팀이 맡고 운영자는 주로 본다**는 것이 확인되어, 범위가 크게 줄었다.

| 만든다 | 만들지 않는다 |
|---|---|
| 실시간 요약 | 학생·선생님 등록 |
| 오늘 집계 | 담임 배정 |
| 준비 실패 목록 | 반복 시간표 편집 |
| 크레딧 경고 목록 | CSV 임포트·일괄 처리 |
| 세션 검색 | 크레딧 수동 조정 |

CSV 임포트와 대량 폼이 빠진 것이 이 결정의 가장 큰 효과다. 그것들이 있었다면 이 문서는 훨씬 큰 프로젝트를 정의했을 것이다.

### 1.1 확정된 전제

| 항목 | 값 | 근거 |
|---|---|---|
| 운영자의 주 업무 | **모니터링** | 인터뷰 |
| 관측 시점 | **실시간 요약 + 사후 상세** | 인터뷰 |
| 수업 시작 기록 | **시작 + 주기적 생존신호** | 인터뷰 |
| 배치 | **별도 앱**, 인증을 먼저 | 인터뷰 |
| 인증 방식 | **자체 로그인** (이메일+비밀번호) | 인터뷰 |

## 2. 순서 — 기능 먼저, 인증은 뒤로 (2026-08-08 변경)

```
1. 시작·생존신호    POST /sessions/:id/start, /heartbeat + 90초 정리 배치
2. 집계 API        운영자용 조회 엔드포인트
3. admin-web       별도 앱
4. 인증            서비스를 확인한 뒤 별도로 발전시킨다
```

당초 이 문서는 인증을 1번에 두었다. **기능 구현을 먼저 보고 인증은 그 뒤에 발전시키기로 결정되었다.**

### 2.1 그래서 반드시 지켜야 하는 것 — 만드는 것과 띄우는 것은 다르다

선생님 화면은 자기 담당 학생만 본다. **운영자 화면은 전체 아동의 보호자 연락처를 본다.**

인증 없이 **만드는 것**은 문제가 없다. 인증 없이 **접근 가능한 곳에 띄우는 것**은 URL을 아는 누구에게나 전체 아동 개인정보를 여는 것이다. 이 둘을 구분하지 않으면 개발 편의가 그대로 사고가 된다.

따라서 인증이 붙기 전까지 **다음 두 가지를 대체 안전장치로 강제한다**:

1. **운영자 API 서버는 `127.0.0.1` 에만 바인딩한다.** 외부 인터페이스에 열지 않는다.
2. **운영자 전용 엔드포인트는 공유 시크릿 헤더를 요구한다.** 값은 `.env` 에 두고 커밋하지 않는다.

이것은 인증이 아니다 — 시크릿을 아는 모두가 같은 권한을 갖고, 누가 무엇을 봤는지도 남지 않는다. **"실수로 노출되는 것"만 막는 장치**이며, §5의 인증이 도입되는 시점에 걷어낸다.

**운영 환경 배포는 §5의 인증이 완료된 뒤에만 한다.** 이 문장이 이 문서에서 가장 중요하다.

## 3. 시작과 생존신호

### 3.1 지금은 `IN_PROGRESS` 를 아무도 쓰지 않는다

`SessionStatus` 에 `IN_PROGRESS` 가 있지만 **그것을 기록하는 코드가 없다.** 선생님이 [수업 시작]을 눌러도 서버는 모르고, `POST /sessions/:id/end` 만 호출된다.

따라서 현재 상태로 운영자의 "지금 진행중" 은 **항상 0** 이다. 실시간 요약은 이것을 메우지 않으면 성립하지 않는다.

### 3.2 두 엔드포인트

| 엔드포인트 | 동작 |
|---|---|
| `POST /sessions/:id/start` | 상태를 `IN_PROGRESS` 로, `startedAt` 기록 |
| `POST /sessions/:id/heartbeat` | 30초마다. `lastHeartbeatAt` 갱신 |

`Session` 에 `startedAt`, `lastHeartbeatAt` 두 컬럼을 더한다.

### 3.3 이것이 메우는 또 하나 — 이미 정의된 안전장치

본 설계 §4.5는 **"선생님 연결 소실 90초 후 자동 종료"** 를 안전장치로 정했다. 방치된 방을 치우기 위한 것이다. 그러나 서버가 선생님의 생존을 알 방법이 없어 **구현 경로가 없는 채로 남아 있었다.**

생존신호가 그것을 가능하게 한다. `lastHeartbeatAt` 이 90초를 넘긴 `IN_PROGRESS` 세션을 정리하는 배치를 붙인다. 즉 생존신호는 운영자 화면만을 위한 기능이 아니라, **이미 합의된 요건을 처음으로 실행 가능하게 만드는 것**이다.

### 3.4 부하

동시 3,000 세션 × 30초당 1회 = **초당 약 100 요청.** 문제되지 않는다.

`lastHeartbeatAt` 은 같은 행을 반복 갱신하므로 쓰기가 몰린다. 초당 100 쓰기는 PostgreSQL에 부담이 아니지만, 동시 세션이 크게 늘면 이 지점을 먼저 본다.

## 4. 화면

### 4.1 실시간 요약

10초 폴링. 숫자만이며 목록이 아니다.

```
지금 진행중 1,204  ·  연결 끊김 17  ·  준비 실패 43  ·  생존신호 끊김 3
```

폴링으로 충분한 이유는 **집계값만 보내기 때문**이다. 세션별 상태를 실시간으로 밀었다면 SSE나 WebSocket과 팬아웃 설계가 필요했겠지만, 숫자 넷은 COUNT 질의 몇 개다.

### 4.2 오늘 집계

예정 / 진행 / 종료 / 노쇼 / 휴강 건수. 사후 확인용이며 실시간일 필요가 없다.

### 4.3 준비 실패 목록

학생, 담임, 수업 시각, 실패 항목(카메라/마이크/네트워크). **선생님이 유선 안내할 대상 목록**이며, 화면 설계 §6이 요구한 "운영·선생님 쪽에 실시간으로 보여야 한다"를 충족한다.

### 4.4 크레딧 경고 목록

`warn` 이 참인 등록. 편성 설계 §5.2가 경고를 둔 이유는 **크레딧이 쌓이기만 하고 소진할 슬롯이 없어지는 상황을 사람이 알아채게** 하려는 것인데, 지금 그것을 볼 화면이 없다. 이 목록이 그 자리다.

### 4.5 세션 검색

학생명·선생님명·날짜로 조회. 문의 대응용이다. 보호자가 "어제 수업이 이상했어요" 라고 하면 운영자가 찾아볼 수 있어야 한다.

## 5. 인증

### 5.1 교체 가능한 계층으로 만든다

사내 SSO 협의가 끝나면 이 계층만 갈아끼운다. 이 프로젝트에서 같은 방식이 세 번 값어치를 했다 — 학습화면 슬롯, `VideoEngine`, 편성 스텁. 특히 편성 스텁은 백엔드가 생겼을 때 **화면 코드를 한 줄만 바꾸고 끝났다.**

### 5.2 모델

```
Account {
  id, email, passwordHash,
  role: TEACHER | OPERATOR,
  teacherId?,          // TEACHER 일 때 Teacher 와 연결
  disabledAt?          // 퇴사자 비활성화
}
```

### 5.3 결정 사항

- 비밀번호 해시는 **argon2id**. bcrypt를 쓰지 않는다.
- 세션 토큰은 **httpOnly 쿠키**. `localStorage` 에 두지 않는다 — XSS 한 번에 털린다.
- `VITE_TEACHER_ID` 를 **삭제**하고 토큰의 `teacherId` 로 대체한다. 화면 설계 오픈이슈 #3a가 이 시점에 닫힌다.
- 로그인 실패 횟수 제한을 둔다.
- 운영자의 조회 행위를 로그로 남긴다. 연락처 열람 기록(화면 설계 §6.2)과 같은 성격이다.

## 6. 우려사항

### 6.1 자체 로그인의 진짜 비용은 로그인 화면이 아니다

**비밀번호 재설정, 퇴사자 비활성화, 계정 잠금 해제를 우리가 책임진다.** 선생님 3,000명 규모에서 이것은 상시 운영 업무가 된다. 최소한 운영자가 계정을 비활성화하는 경로는 처음부터 있어야 한다.

사내 SSO로 가면 이 부담이 통째로 사라진다. §5.1의 교체 가능한 계층이 그래서 중요하다.

### 6.2 운영자 계정이 최고 위험 자산이 된다

전체 아동 정보에 접근하는 계정이다. 실패 제한과 접근 로그는 선택 사항이 아니다. 운영자 계정 수를 최소로 유지하는 운영 정책도 함께 필요하다.

### 6.3 생존신호는 선생님 브라우저가 켜져 있다는 뜻일 뿐이다

탭이 열려 있으면 신호는 간다. 선생님이 자리를 비웠는지는 알 수 없다. 이 신호로 판단할 수 있는 것은 **"세션이 방치되었는가"** 이지 **"수업이 잘 되고 있는가"** 가 아니다. 운영자 교육 자료에 명시한다.
